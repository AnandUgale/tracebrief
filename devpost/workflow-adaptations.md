# Workflow provenance and explicit delegation

The real Devpost Learn Skill Pack was obtained from https://github.com/challengepost/learn-ai-basics and read before use. Its six skills are installed under .agents/skills/. The project directory was initially empty; installed curriculum material is not treated as project implementation or completed planning.

The human explicitly instructed the agent to consult ChatGPT Pro Deep Research for idea selection and not ask them routine questions. This takes precedence over curriculum interviewing and routine approval defaults. Product/technical decisions must be attributed to their actual source (Pro/agent under delegation), not falsely described as personal human authorship or review. Human learning, testing, feedback, reflections and submitted artifacts must never be fabricated.

Stage 1 recorded known constraints and explicit delegation in the ignored learner profile. Scope, PRD and spec were produced in order before the implementation commits. The third build slice now has technical documentation, an app map, fourteen passing regressions and saved browser evidence. Ordinary Pro code critique produced specific repairs; final-demo critique prioritized delivery over new features.

The actual 5-build and 6-ship instructions were read again during final preparation. Their default human interviews/checkpoints and prohibition on drafting submission prose conflict with the human's explicit delegation and later request for a prepared submission draft. That direct instruction governs this preparation. Draft prose is identified as AI-assisted; personal reflections, survey answers, human testing and personal sign-off are not invented. The literal human-led curriculum activities remain unperformed. No claim is made that the organizer has approved this adaptation.

The original private Git history is preserved. A separate source snapshot excludes that history, personal learner context, installed curriculum files and private research. The curriculum source revision remains in the public provenance file; the curriculum itself is not bundled with the app.

No spending, registration, publication or submission has occurred. The user handles authentication secrets directly in the browser. Binding/security/final submission handoffs remain required where applicable.
