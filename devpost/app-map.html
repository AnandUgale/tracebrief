The three-stop route

  1. app.js → generate() reads the current controls and calls the pure engine. Invalid inputs receive a visible message.
  2. engine.js → splitSentences() preserves original offsets. createBrief() selects exact source sentences, returns focus coverage and calls findReviewHints().
  3. app.js → render() / selectSource() renders text safely and highlights the selected source. engine.js → exportMarkdown() keeps source references in the portable result.

To change this, start here

Selection or source boundaries

Use engine.js, then the corresponding fixtures in test/engine.test.js. Preserve the invariant that every sentence equals its original text slice.

Focus coverage or review hints

Use createBrief() for source presence/selection states, findReviewHints() for comparisons, and render() for their labels. Hints remain suggestions for context review.

Layout and interface copy

Use index.html and styles.css. Test the narrow layout and keyboard source selection after changing controls or text.

A practice to reuse

Turn a vague concern into a small failing fixture before fixing it. Pro's phase-comparison example exposed a false-positive review hint; the new test first failed, then passed after an explicit entity guard. The same method verified headings, numbered lists, deadline revisions and omitted focus topics.

Run it again

Open index.html, or run node server.js and visit the workspace. Run node --test for the regression suite.
